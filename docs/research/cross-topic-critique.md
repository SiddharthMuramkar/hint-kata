## 2. Load-bearing questions a spec still needs answered

1. **Audience and access.** Is this just for you or public? That decides auth, abuse protection, Vercel Hobby non-commercial status and protecting the production domain. No topic covered rate limiting or abuse of `/api/chat`.
2. **Learner identity and state.** Where do progress, quiz scores, grades and chat history live: localStorage, or Neon keyed to a GitHub login? Neon Managed Better Auth doesn't support a separate frontend and backend. Nobody researched GitHub OAuth in FastAPI.
3. **Content model and authoring.** Are lessons Markdown in the repo or rows in the DB? What is the quiz storage schema? Who writes 36 lessons, and what is the review gate (Claude draft → fact-checker subagent → you)? Must every claim carry a citation?
4. **Release 1 scope.** Only FastAPI proposed a "best 3". The other tracks list 12 lessons each with no MVP cut.
5. **How hands-on work is verified.** Local pytest with a pasted result (trust-based)? GitHub template repo plus server-side check-runs, which needs a GitHub App or token? Or the LLM grader on free text?
6. **Corpus boundaries.** Are the pinned versions per track fixed? Does the tutor answer only from pinned docs or also flag newer ones? Is there one index or a per-track filter? Is release-notes.md in or out?
7. **Monthly budget ceiling, and who pays.** This covers Anthropic, embeddings, Vercel, Neon and the claude-code-action. It also fixes which caps get set in each provider console.
8. **Privacy.** Are learner chat transcripts stored? Does Logfire `include_content` stay on? What is the retention period?
9. **Database stack.** Raw psycopg 3, or SQLAlchemy 2 (psycopg 3 driver) plus Alembic, or SQLModel? Where do migrations run? It is unverified whether `DATABASE_URL_UNPOOLED` is present during a Vercel Python build.
10. **Machine and plan facts.** Actual Mac RAM. Claude plan (Pro or Max), which affects the workflows setting, the OAuth token for Actions and quota. The Claude Code version, which must be at least 2.1.295 for `onFailure`.
11. **Repo visibility.** The site repo and the practice repo: public or private? That determines whether rulesets work on Free, the 60-day schedule auto-disable, Actions minutes, and prompt-injection exposure.
12. **Eval gates.** Which pydantic-evals thresholds block a deploy or a prompt change, and how often do evals run?

## 3. Five biggest risks for a solo beginner

1. **Infrastructure crowds out learning.** There are 6+ services (Vercel, Neon, Anthropic, an embeddings vendor, Logfire, GitHub), several beta features (Services, schema-only branches, the onFailure hook) and 36 lessons. Mitigation: build one thin vertical slice with 3 lessons, then expand.
2. **Content goes stale fast.**
   - Pydantic AI V2 ships about 4 releases a week.
   - FastAPI breaks things in minor releases.
   - Claude Code behavior is gated across many 2.1.2xx versions.
   - setup-uv has no floating tags.
   - LLM priors and tutorials still describe Pydantic AI V1.

   Mitigation: exact pins, a CI job that runs the lesson code, version stamps on lessons and the PR-gated re-sync.
3. **Cost and security exposure.**
   - **Public LLM endpoints.** Mitigation: a Vercel WAF rate limit (Hobby allows 1 rule per project, IP key, 1M requests included), Pydantic AI `UsageLimits` and provider spend caps.
   - **Hooks fail open** by default.
   - **Broad-access MCP servers.** This session's own environment already shows **two Neon MCP servers in write mode** plus a Vercel connector, which is exactly the duplicate and broad-access risk cc-mcp flagged.
   - **PAT and OAuth tokens** stored in Actions.

   Branch protection and read-only MCP are the real controls.
4. **Serverless integration traps that are hard to debug.**
   - PgBouncer transaction mode breaks session `SET` and prepared statements.
   - Neon scale-to-zero and Vercel cold starts stack on top of each other.
   - Spans are dropped unless flushed.
   - Lifespan cleanup is capped at 500ms.
   - Services routing keeps the `/api` prefix.
   - Grading or logging that runs after the response is sent can be cut off.
5. **Unreliable tutoring and grading undermines the "make it stick" goal.** The judge can't run at temperature 0, models default to V1 knowledge, Haiku's citation faithfulness is unproven, and the C3 citation/streaming tension is unresolved. Mitigation: 20–30 hand-graded calibration cases, show the rubric to the learner, server-rendered citation links only, and a Haiku-vs-Sonnet eval before committing.

## 4. Interview decisions (recommended option first, with evidence)

- **D1 Audience.** Recommended: personal first. Lessons public, AI endpoints gated, either by Vercel Authentication on All Deployments (C13, confirm on Hobby) or by a single allowlisted GitHub login. Add the WAF rate-limit rule either way. The alternative, fully public, needs auth plus quotas first.
- **D2 Deploy topology.** Recommended: a single FastAPI app serving the Vite build through `app.frontend("/", directory="dist")`, which is GA and promoted to CDN by Vercel, after a day-1 build spike. Services (beta) is the second choice, two projects the fallback.
- **D3 LLM access.** Recommended: direct Anthropic BYOK with a console spend cap (C4). Gateways come later.
- **D4 Models.** Recommended: Haiku 5.5 tutor (effort low or medium, cached instructions), Sonnet 5.5 grader and quiz generator with NativeOutput, all model IDs in env. Confirm with a 30-case eval.
- **D5 Embeddings.** Recommended: `voyageai:voyage-4-lite` at 1024 dims (200M free tokens make re-embeds free; HNSW-safe). If you don't want another account: OpenAI `text-embedding-3-small` at 1536 dims. Store the model and dimension on each row either way.
- **D6 Neon↔Vercel.** Recommended: defer the integration. Use one static `preview` Neon branch as the Preview DATABASE_URL, which keeps you inside the 10-branch limit with no lingering branches. Add the Neon-Managed integration with auto-delete later as a GitHub-track lesson. Avoid Vercel-Managed (6-month branch retention).
- **D7 Claude Code docs.** Recommended: links, metadata and original summaries only (C7). Ingest the MIT-licensed claude-code-action docs and github-mcp-server docs instead.
- **D8 Tutor architecture.** Recommended: the C3 tool-plus-`str` output with validated `[n]` markers, `sdk_version=7`, and citations rendered server-side from the chunk table.
- **D9 Hands-on verification.** Recommended for release 1: downloadable starter plus local `uv run pytest` with pasted output. The GitHub track uses a public practice repo. Server-side check-run verification waits until identity exists.
- **D10 Identity and progress.** Recommended: localStorage progress in release 1, with GitHub OAuth as the release 2 path (it fits the GitHub track and check-runs). Skip Neon Better Auth for now.
- **D11 Repo visibility.** Recommended: public site repo and public practice repo. Free-plan rulesets then work and Actions minutes are free. Use no `pull_request_target`, and make claude-code-action trigger only on `@claude` from the owner. Add `workflow_dispatch` and keep the repo active to avoid the 60-day schedule auto-disable.
- **D12 claude-code-action.** Recommended: on-demand `@claude` only, with an API key and a spend cap, or skip it in release 1 and use local `/code-review`. Use the OAuth token only after checking your plan's terms.
- **D13 Release 1 scope.** Recommended: 3 lessons per track at most, with one track built first end to end: FastAPI L1 Run it right, L6 Dependency injection, L12 SSE. That proves tutor, quiz, grader and re-sync before writing more.
- **D14 Re-sync.** Recommended: a weekly off-hour cron plus `workflow_dispatch` that opens a PR with the manifest diff; the merge triggers hash-diff upserts (C11).
- **D15 Pinning.** Recommended: `pydantic-ai-slim==2.56.0`, `fastapi>=0.143,<0.144`, docs ingested at the matching tag SHA, and the tutor answering from pinned docs while saying newer docs may differ.
- **D16 Database stack.** Recommended: Postgres 17/18 in us-east-1, SQLAlchemy 2 Core with the psycopg 3 driver, `pool_pre_ping` and a tiny or Null pool, Alembic on the unpooled URL run from GitHub Actions (the build-time env is unverified), and raw SQL for the HNSW + tsvector RRF query.
- **D17 Claude Code setup.** Recommended:
  - Commit `"outputStyle": "Learning"` to `.claude/settings.json`.
  - Write Python hooks in exec form.
  - Pin Claude Code to at least 2.1.295.
  - Ask before every `git push`.
  - Use rulesets as the real lock.
- **D18 Monthly budget.** Recommended starting point, about $5–20 a month: Vercel Hobby, Neon Free, Logfire Personal, Voyage free tier, Anthropic capped at a number you choose. The user needs to pick the number.

- **CONFIRMED: Vercel Python runtime versions are 3.12 (default), 3.13 and 3.14. FastAPI deploys with zero config: Vercel looks for a FastAPI instance named `app` in app.py, index.py, server.py, main.py, wsgi.py or asgi.py, at the repo root or inside src/ or app/, or at the module path set in pyproject.toml.** [high] _(via Octen extract (versions); Tavily extract (entrypoint list); Octen extract of https://vercel.com/docs/frameworks/backend/fastapi (tool.vercel.entrypoint))_
  Override the location with `[tool.vercel] entrypoint = "backend.server:app"` in pyproject.toml. Set the version with pyproject `requires-python`, `.python-version` or Pipfile.lock; an unsupported version falls back to the default. Dependencies can come from pyproject.toml (optionally with uv.lock), requirements.txt or Pipfile. The whole FastAPI app becomes a single Vercel Function. Tavily extract of the same Python page also listed the changelog entry 'Python 3.13 and 3.14 are now available'.
  Source: <https://vercel.com/docs/functions/runtimes/python>
- **CONFIRMED: maximum function duration with Fluid compute is 300 s (default and maximum) on Hobby. Pro defaults to 300 s, allows up to 800 s (generally available) and 1800 s as a beta 'extended maximum'. Memory is 2 GB / 1 vCPU on Hobby and up to 4 GB / 2 vCPU on Pro. Request and response payloads are capped at 4.5 MB.** [high] _(via Octen extract)_
  Values above 800 s need function-level config and specific Node.js, Bun or Python versions. Streamed responses count toward the duration. A timeout returns 504 FUNCTION_INVOCATION_TIMEOUT. ### Recommendations
- Run release 1 on Vercel Hobby: it is owner-only and non-commercial. Budget Vercel Pro ($20/month) from the day accounts or payments go live, because payments count as commercial use.
- Keep each tutor chat or grading call under Hobby's 300 s limit. Stream the tutor over SSE using `VercelAIAdapter.dispatch_request(request, agent=agent, sdk_version=6)` with an AI SDK v6 `useChat` frontend, or a plain FastAPI StreamingResponse.
- To keep things simple, serve the frontend from FastAPI or as static assets in one function. Use the beta `services` key (not `experimentalServices`) only if you need a separate JS framework, and expect config churn.
- Run the docs re-sync (scrape, chunk, embed, upsert) as a GitHub Actions `schedule` job instead of a Vercel cron. Hobby cron is daily only with ±59 min precision, and ingestion is a good lesson for the GitHub track. Do embedding in CI or via an API, not inside the Vercel function, to stay within bundle size and memory limits.
- Anthropic has no embeddings API, so use Pydantic AI `Embedder` with an API provider (`openai:text-embedding-3-small` or `voyageai:`). Avoid local sentence-transformers on a low-RAM Mac and in Vercel bundles. Store the vectors in Neon pgvector 0.8.x with an HNSW index.
- Use `claude-haiku-5-5` for hints, quiz feedback and most rubric grading, keeping prompts under 100K tokens to stay in the cheap tier. Reserve `claude-sonnet-5-5` for harder open-ended rubric grading. Run a nightly batch at 50% off to regenerate questions.
- One Neon Free project is enough (1 GB storage, 100 CU-hours, scale-to-zero). If Vercel preview branching is on, add branch expiration or cleanup, because Free caps branches at 10 per project and offers no paid extras.
- For the GitHub track, either pay for Pro ($4/month) so private repos get rulesets, branch protection and CODEOWNERS, or practice on a public sandbox repo on Free. Teach rulesets over classic branch protection.
- Because the learner is solo, prefer 'require a pull request' plus required status checks and an admin bypass over 'required approving reviews'. A sole author cannot provide their own approval; this is well-known but was not re-verified in this pass.
- Pin `pydantic-ai==2.56.0` in lessons and record the version in each lesson's metadata. Point the docs scraper at pydantic.dev/docs/ai/ (follow redirects, or use llms.txt) and re-validate quiz answers on each sync, since releases ship about weekly.
- Build the 'GitHub in the Claude Code era' track around confirmed features: `claude -w <name>` / `claude -w #123` worktrees, `/goal <condition>`, `/loop 10m <prompt>` (expires after 7 days), dynamic workflows saved to `.claude/workflows/*.js`, and the `Learning` output style.

### Risks
- Neon Free storage is inconsistent across Neon's own pages: 1 GB per project (pricing page and plans doc crawled 2026-10-13/14) versus 0.5 GB (an older FAQ and one cached extract). Treat 0.5 GB as the safe planning floor.
- Vercel Services is in beta, and its config model has already changed once (experimentalServices to services). Building on it can force rework.
- Pydantic AI ships minor releases every few days (4 in 12 days). Lesson code, quizzes and RAG citations can drift, and the docs domain move (ai.pydantic.dev to pydantic.dev/docs/ai) can break naive scrapers and old citation links.
- Claude Code features are version-gated and change fast (for example /goal resume behavior changed at v2.1.239, and GitLab MR worktrees need v2.1.233+). Lessons need a minimum-version note.
- Claude Haiku 5.5 pricing is tiered: prompts over 100K tokens cost 5x more ($0.50/$2.50). Large retrieved contexts could unexpectedly cross that threshold.
- Vercel's 4.5 MB request/response payload limit, and the 300 s Hobby duration that includes streaming time, constrain file uploads and long tutor sessions.
- GitHub pricing is shifting: Team shows a 'first 12 months' introductory price, and the postponed self-hosted runner charge could return.
- Tavily hit its plan usage limit (HTTP 432) partway through, after about 4 searches and 4 extracts. Later checks used only Octen and Firecrawl, so some facts were confirmed by two engines rather than three.
