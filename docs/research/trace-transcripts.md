# Trace transcripts: definition and pipeline

_Research archive. Checked against primary sources on 2026-10-14. Facts about fast-moving tools (Claude Code, Pydantic AI, FastAPI, GitHub, OpenRouter) go stale quickly: re-check before relying on a number._

- **Needed by:** Phase 1 (scripted Pydantic AI runs, this repo's PR timelines); Phase 2 (Claude Code session transcripts)
- **Licence / attribution notes:** Transcript tools cited: claude-code-log (MIT), claude-code-transcripts (Apache-2.0).
- **Covers:** what a trace transcript is, schema, capture pipelines, storage, RAG policy, UX, Logfire limits

## What "the official docs plus trace transcripts" should mean: Pydantic AI run traces, Claude Code session transcripts, Logfire export/MCP, and prior art for annotated traces as teaching material

**Summary.** The most useful reading of "trace transcripts" is an annotated, redacted, step-by-step replay of a real agent run, stored in a schema the site owns. Each step links to citations in the official docs and carries quiz checkpoints. It is neither a raw Logfire trace nor a raw Claude Code JSONL file. There are two source kinds. (a) Pydantic AI agent runs, for tracks 1 and 2: capture them with agent.iter() (UserPromptNode → ModelRequestNode → CallToolsNode → End) and with all_messages_json() / ModelMessagesTypeAdapter, which round-trip losslessly and carry run_id and conversation_id, the same IDs that appear on the OTel spans. (b) Claude Code sessions from building this very site, for track 3: pair them with the PR's GitHub timeline (branch → PR → review → CI → merge) to make worked examples. Claude Code transcripts live at ~/.claude/projects/<project>/<session-id>.jsonl. Anthropic says the format is internal and changes between versions, and the files are deleted after 30 days by default. The site therefore needs its own tolerant normalizer, run from a SessionEnd hook that receives transcript_path. Logfire is good for capture and as a lesson subject: instrument_pydantic_ai, SQL query API, hosted MCP server, public trace links. It cannot be the content store, because the free Personal plan keeps data for 30 days and allows at most 500 query-API requests a day. For deterministic, CI-reproducible Pydantic AI traces, use FunctionModel with scripted realistic tool calls. TestModel produces placeholder arguments such as 'a', so it makes poor lesson content. Real-model runs should be captured once and frozen. Mature renderers exist: claude-code-log (MIT, v1.7.0, Oct 2026, the most active) and simonw/claude-code-transcripts (Apache-2.0, v0.6, local mode works, web mode broken). Redaction tools are weak. A path/identifier/secret sanitizer exists but does not scrub prose PII, and Claude Code's own redaction has had recent gaps. So human review before committing is a hard gate. Prior art supports the format. Anthropic says reading transcripts is a critical agent-development skill, Hamel Husain teaches open-coding of traces, and the ESSE tutor (arXiv 2608.25180) grades learners' self-explanations of worked-example steps with an LLM and releases hints in gated layers. That maps directly onto this site's think-deeper questions and hint-before-answer tutor. Tool note: Tavily worked for 3 searches, then returned HTTP 432 (plan usage limit) on both search and extract. The rest of the research used Firecrawl, Octen, gh api, curl, and a read-only local jq inspection.

**Engines used:** Firecrawl: firecrawl_scrape (Pydantic AI message-history, Claude Code sessions/headless/hooks docs, Logfire Pydantic AI integration, Logfire query API, Pydantic AI Logfire integration, claude-code-log repo), firecrawl_search (capture_run_messages, testing guide, prior art, Hamel error analysis, GitHub timeline API), firecrawl_developer_search (claude-code-action execution_file, SWE-agent trajectory inspector), firecrawl_research_search_papers + firecrawl_research_read_paper (ESSE arXiv 2608.25180, worked-example literature); Tavily: tavily_search succeeded 3 times (Claude Code JSONL format, Logfire gen_ai usage attributes, Logfire query client). Later tavily_search and tavily_extract calls failed with HTTP 432 'exceeds your plan's set usage limit'.; Octen: search (simonw transcripts, agent.iter nodes, Simon Willison posts, Anthropic evals post, viewers, replay UIs), broad_search (Logfire pricing/MCP/query limits; transcript viewers and redaction tools), extract (Logfire pricing + MCP guide, public traces/conversations, scrubbing, query limits, Simon Willison post); gh api (read-only): repo metadata, licenses, stars and releases for transcript tools; claude-code-transcripts README; anthropics/claude-code CHANGELOG grep; curl (read-only GET): llms.txt/llms-full.txt availability and redirects; PyPI JSON metadata; Local read-only jq inspection of record types and keys (no content) in this session's Claude Code JSONL

### Findings

- **Pydantic AI exposes the full run as messages: all_messages()/new_messages() plus JSON-bytes variants all_messages_json()/new_messages_json(). ModelMessagesTypeAdapter (TypeAdapter(list[ModelMessage])) with pydantic_core to_jsonable_python/to_json round-trips them via validate_python/validate_json.** [high] _(via Firecrawl (scrape))_
  Message types to render as steps: ModelRequest(parts=[SystemPromptPart|UserPromptPart|ToolReturnPart|RetryPromptPart]), ModelResponse(parts=[TextPart|ToolCallPart|ThinkingPart], usage=RequestUsage(input_tokens, output_tokens, cost), model_name). This is the canonical raw format to store for Pydantic AI traces. Note: ai.pydantic.dev/message-history/ now redirects to pydantic.dev/docs/ai/core-concepts/message-history/.
  Source: <https://pydantic.dev/docs/ai/core-concepts/message-history/>
- **An AgentRunResult can be stored directly as a field on a Pydantic model. The round-trip preserves the output, messages and new-message boundary, usage, run and conversation IDs, metadata, and trace context. AgentRunResult.conversation bundles history, usage and pending deferred calls.** [high] _(via Firecrawl (scrape))_
  Example: class StoredRun(BaseModel): result: AgentRunResult[str], then model_dump_json()/model_validate_json(). A trace transcript's raw layer can therefore be one validated JSON blob that re-renders even after a library upgrade. For streamed runs, store StreamedRunResult.result after the stream finishes.
  Source: <https://pydantic.dev/docs/ai/core-concepts/message-history/#storing-complete-run-results>
- **Every ModelRequest and ModelResponse carries run_id and conversation_id, which are emitted on the OTel agent span as gen_ai.agent.call.id and gen_ai.conversation.id. This is a free join key between stored messages and Logfire spans.** [high] _(via Firecrawl (scrape))_
  You can pass run_id='...' to pre-mint the ID, for example the trace-transcript slug, and conversation_id='new' to fork. This lets a lesson step deep-link to the matching Logfire span while it is still retained.
  Source: <https://pydantic.dev/docs/ai/core-concepts/message-history/#correlating-runs-with-run_id-and-conversation_id>
- **capture_run_messages() is a context manager that captures the messages exchanged even when the run raises. Partial state is also kept on cancellation (RunCancelled.all_messages()).** [high] _(via Firecrawl (search))_
  Useful for 'what went wrong' lessons such as ModelRetry, UnexpectedModelBehavior and usage-limit exceptions, where result.all_messages() is unavailable because the run raised.
  Source: <https://pydantic.dev/docs/ai/api/pydantic-ai/agent/>
- **agent.iter() yields the agent graph nodes in order: UserPromptNode → ModelRequestNode → CallToolsNode → … → End(FinalResult). Node streams expose events (PartStartEvent, PartDeltaEvent, FunctionToolCallEvent, FunctionToolResultEvent, FinalResultEvent).** [high] _(via Octen (search))_
  This maps one-to-one onto 'watch the agent work' steps (prompt assembled → model asked → tool called → tool returned → final output). Agent.is_model_request_node / is_call_tools_node / is_end_node help classify nodes. The docs example log reads like a ready-made step narration ('[Tools] The LLM calls tool=weather_forecast …').
  Source: <https://pydantic.dev/docs/ai/core-concepts/agent/>
- **For reproducible runs, Pydantic AI recommends TestModel or FunctionModel plus models.ALLOW_MODEL_REQUESTS=False. TestModel fills tool arguments with schema-valid placeholders (e.g. location='a', forecast_date='2024-01-01'). FunctionModel lets you script exact, realistic tool calls per turn.** [high] _(via Firecrawl (search))_
  Use FunctionModel for curated lesson traces that CI can regenerate and diff on every Pydantic AI upgrade. Use TestModel only for 'what does the agent loop look like' skeletons. Real-model traces should be captured once and frozen.
  Source: <https://pydantic.dev/docs/ai/guides/testing/>
- **logfire.instrument_pydantic_ai() emits invoke_agent, chat and execute_tool spans. Key attributes: pydantic_ai.all_messages, gen_ai.input.messages, gen_ai.output.messages, gen_ai.tool.call.arguments, gen_ai.tool.call.result, gen_ai.usage.* per request, and gen_ai.aggregated_usage.* on the agent span. The default instrumentation version is 5 (6 is opt-in).** [high] _(via Firecrawl (scrape+query); Tavily (search) for aggregated-usage details)_
  It can run without Logfire's backend: logfire.configure(send_to_logfire=False) plus OTEL_EXPORTER_OTLP_ENDPOINT=http://localhost:4318 sends to any local OTel backend. InstrumentationSettings(include_content=False) drops prompts and completions. Version bumps change attribute shapes; for example, v6 moves tool results to role='tool'.
  Source: <https://pydantic.dev/docs/ai/integrations/logfire/>
- **Logfire attaches operation.cost (USD, priced with genai-prices) and token counts to LLM spans, and both can be queried in SQL, e.g. attributes->'gen_ai.usage.input_tokens' and attributes->'operation.cost'.** [high] _(via Tavily (search))_
  Lets each trace step show a token/cost meter, a cheap way to make traces feel game-like. The UI's browser-side cost estimate cannot be queried; only stored attributes can.
  Source: <https://pydantic.dev/docs/logfire/cookbook/track-llm-cost>
- **The Logfire Query API is POST https://logfire-us.pydantic.dev/v2/query (EU: logfire-eu), authenticated with a read token as a Bearer header. It returns JSON, NDJSON, Arrow or CSV over tables 'records' and 'metrics'. Default limit is 100 rows, maximum 10,000. The Python client is LogfireQueryClient.query_json_rows(sql, min_timestamp=…).** [high] _(via Firecrawl (scrape query); Tavily (search) for client API at https://pydantic.dev/docs/logfire/api/query_client)_
  Calling without min_timestamp is now deprecated, and query_json() is deprecated in favour of query_json_rows(). Use it in a one-shot export script to pull a run's spans (by trace_id or gen_ai.agent.call.id) into the trace-transcript JSON before retention expires.
  Source: <https://pydantic.dev/docs/logfire/manage/query-api>
- **Logfire's Personal plan is free with a hard cap of 10M records/month (ingestion pauses at the cap). It includes 3 projects, 30-day retention, 1 seat plus 2 read-only guests, and at most 500 Query API requests/day. Team also has 30-day retention; Growth goes up to 90 days.** [high] _(via Octen (broad_search + extract))_
  Logfire therefore cannot be the durable home for lesson traces. Export what you need into the site's own store, or link only to short-lived public traces. 10M records is ample for one learner.
  Source: <https://pydantic.dev/pricing>
- **Logfire hosts a remote MCP server (https://logfire-us.pydantic.dev/mcp). Its tools include query_run (SQL), query_schema_reference, query_find_exceptions_in_file, project_list and project_logfire_link, plus dashboard, alert and issue tools. Install it in Claude Code with 'claude mcp add --transport http logfire …' or the logfire plugin.** [high] _(via Octen (extract))_
  It has its own concurrency limit and a daily query budget per organization. The docs warn that telemetry returned by MCP is untrusted data, not instructions. This makes it a natural track-3 lesson ('ask Claude Code, via MCP, why my agent retried') but not a production dependency of the tutor.
  Source: <https://pydantic.dev/docs/logfire/guides/mcp-server>
- **Logfire Public Traces and Public Conversations create shareable links. A public conversation shows one LLM span as chat bubbles and omits system instructions and tool definitions. Links stop working when the span ages out of plan retention, even if set to 'Never' expire. Pydantic's own docs embed a public trace as the worked example for instrumentation.** [high] _(via Octen (extract); Firecrawl (scrape) of https://pydantic.dev/docs/logfire/integrations/llms/pydanticai for the embedded public trace)_
  This is prior art for 'traces as docs content'. On the free plan, an embedded link breaks after 30 days, so any live link from a lesson must be optional, with the stored transcript as the fallback.
  Source: <https://pydantic.dev/docs/logfire/observe/public-conversations/>
- **Claude Code stores each session at ~/.claude/projects/<project>/<session-id>.jsonl, where <project> is the cwd with non-alphanumerics replaced by '-'. Anthropic states the entry format is internal and changes between versions, so direct parsers can break on any release. Default retention is 30 days (cleanupPeriodDays). /export writes a plain-text rendering.** [high] _(via Firecrawl (scrape); also Tavily (search))_
  Supported structured interfaces: claude -p --output-format json|stream-json (with --verbose and --include-partial-messages), claude -p --resume <id>, the transcript_path field passed to hooks and status lines, and the Agent SDK. Storage can be moved with CLAUDE_CONFIG_DIR, and writes suppressed with --no-session-persistence.
  Source: <https://code.claude.com/docs/en/sessions>
- **Every Claude Code hook receives session_id, transcript_path, cwd, permission_mode and hook_event_name. SessionEnd fires when a session terminates (with a reason), and the sessions doc says a SessionEnd hook can archive the transcript.** [high] _(via Firecrawl (scrape query) + sessions doc via Firecrawl)_
  This is the supported capture path for curated sessions: a SessionEnd hook copies transcript_path into a private inbox outside the repo before the 30-day sweep deletes it.
  Source: <https://code.claude.com/docs/en/hooks>
- **Claude Code links sessions to pull requests. 'claude --from-pr <number>' opens the picker filtered to sessions linked to that PR, and pasting a GitHub PR URL into picker search finds the session that created it. Ctrl+B filters by git branch.** [high] _(via Firecrawl (scrape); GitHub timeline docs via Firecrawl (search))_
  This makes it easy to find the exact branch → PR session for a worked example. Pair it with the GitHub REST timeline (GET /repos/{o}/{r}/issues/{n}/timeline, event types reviewed, ready_for_review, head_ref_force_pushed, merged) plus reviews and check-runs to build the GitHub half of the transcript (https://docs.github.com/en/rest/issues/timeline, found via Firecrawl).
  Source: <https://code.claude.com/docs/en/sessions#resume-a-session>
- **A read-only inspection (keys only) of a real JSONL on this Mac (Claude Code session dated 2026-10-14) found 11 record types: user, assistant, attachment, system, file-history-snapshot, file-history-delta, queue-operation, custom-title, agent-name, last-prompt and atis-latch. Message records carry cwd, gitBranch, sessionId, slug, version, permissionMode and uuid/parentUuid. Content blocks are text, thinking, tool_use and tool_result.** [high] _(via Local read-only jq inspection (no search engine))_
  This confirms the docs warning: many non-message record types exist beyond the commonly documented user/assistant/tool shapes. It also shows the privacy surface: absolute paths with the macOS username in cwd, branch names, full tool_result payloads, and thinking text. A normalizer should whitelist record types and fields rather than blacklist them.
  Source: <file://(local Claude Code project dir)>
- **simonw/claude-code-transcripts (Apache-2.0, v0.6 released 2026-01-25, about 1.7k stars, last commit 2026-02-12) converts local JSONL into paginated HTML. It provides an index.html timeline of prompts and commits, GitHub commit links via --repo, --gist publishing and --json to bundle the raw file. Its 'web' commands are broken (issue #77) because they used undocumented APIs.** [high] _(via Octen (search, extract of simonwillison.net post); gh api for license/stars/releases/README)_
  Simon Willison's rationale: project context that used to live in issues now lives in Claude Code conversations, so transcripts should be kept with the code. The tool is mature for one-off HTML viewing and the 'local'/'json'/'all' commands still work. It is quiet but not abandoned, and it has no redaction.
  Source: <https://github.com/simonw/claude-code-transcripts>
- **daaain/claude-code-log (MIT, v1.7.0 released 2026-10-05, 35 PyPI releases, about 1.2k stars, pushed 2026-10-09) is the most actively maintained Python converter. It turns JSONL into HTML and Markdown, with a TUI, date-range filtering, token-usage display and collapsible tool sections. Other viewers include matt1398/claude-devtools (MIT, about 4k stars, v0.5.0 May 2026, desktop viewer), delexw/claude-code-trace (MIT, 377 stars, active Oct 2026), d-kimuson/claude-code-viewer (MIT, about 1.3k) and driangle/vibeview (MIT, new).** [high] _(via Firecrawl (scrape summary); Octen (broad_search) for the other viewers; gh api / PyPI JSON for metadata)_
  Viewers are for browsing, not for producing site content. For the pipeline, either borrow claude-code-log's parsing and Markdown output or write a roughly 200-line tolerant normalizer that targets the site schema. Avoid Electron or desktop apps on a low-RAM Mac. Star counts are as of 2026-10-14.
  Source: <https://github.com/daaain/claude-code-log>
- **claude-code-sessions-sanitizer (MIT, v0.3.1, PyPI; ccs-sanitize CLI) scrubs Claude Code JSONL in layers: path, then configured identifiers (name, email, usernames, hostnames), then secret patterns. Its own docs say it does not read prose: PII typed into prompts or tool output passes through, and human review is still required.** [medium] _(via Octen (broad_search); PyPI JSON API via curl)_
  Use it as one layer, together with a secret scanner, a path rewrite such as /Users/<name>/… → ~/proj/…, and a mandatory human-review flag in the schema. Name the config file generically, because its filename is recorded in the sidecar.
  Source: <https://pypi.org/project/claude-code-sessions-sanitizer/>
- **Claude Code's built-in secret redaction for shared transcripts and debug logs has had several recently fixed gaps. Examples: key names containing zero-width characters, URL passwords with punctuation or %40, values after keys with no value, and invalid JSON lines in the /feedback zip after redaction. An open feature request (#57772) asks for /export --redact.** [medium] _(via gh api (CHANGELOG grep); Octen (broad_search) for issue https://github.com/anthropics/claude-code/issues/57772 and mixed-news coverage)_
  Do not rely on built-in redaction for content you publish into the site, even privately. Redact in your own pipeline and review by hand. The changelog does not make clear whether local JSONL files are redacted at write time.
  Source: <https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md>

It is configurable with logfire.ScrubbingOptions(extra_patterns=[…]) and a callback to un-scrub safe matches.** [high] _(via Octen (extract))_
  Relevant if Logfire spans are exported into traces. The defaults can also over-scrub teaching content, for example a lesson about 'session' handling, so add a callback whitelist for demo-only keys.
  Source: <https://pydantic.dev/docs/logfire/instrument/python/scrubbing/>

  Source: <https://github.com/anthropics/claude-code-base-action>

  Trace annotations should cite the canonical post-redirect URLs plus anchors. A scheduled docs re-sync should store content hashes per chunk, so traces whose cited chunks changed can be flagged for review.
  Source: <https://pydantic.dev/docs/ai/llms.txt>
- **Learning-science prior art maps directly onto trace lessons. The ESSE tutor (arXiv 2608.25180, Sep 2026) presents worked examples one line at a time and asks learners to self-explain each line. An LLM grades correctness (binary) and completeness (expected concepts present / expected) using the expert explanation as context, not as an answer key. Feedback comes in gated layers (Flags → Samples → Feedback → Answer), and students persisted, revised and produced richer explanations.** [high] _(via Firecrawl (research_search_papers + research_read_paper))_
  Replace 'line' with 'trace step' and you have the site's think-deeper loop and hint-before-answer tutor. Related work: faded worked examples (Salden et al., pmid:25164806) and contingent fading tutors (CoMeT, arXiv 2609.22993), which support fading annotations across successive traces.
  Source: <https://arxiv.org/abs/2608.25180>
- **Industry prior art treats reading agent traces as a core skill. Anthropic's 'Demystifying evals for AI agents' says 'Read the transcripts!' and calls reading transcripts a critical skill for agent development. Hamel Husain's error-analysis method has humans open-code at least 30 traces, noting the first upstream failure, before using an LLM to cluster the notes.** [high] _(via Octen (search); Hamel FAQ https://hamel.dev/blog/posts/evals-faq/ via Firecrawl (search))_
  This supports a lesson type where the learner annotates a trace themselves ('find the first thing that went wrong'), graded against the author's annotation. It also suggests later traces be deliberately flawed (bad tool args, retry loops, premature merge) rather than all happy-path.
  Source: <https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents>

### Recommendations
- DEFINE IT: a 'trace transcript' is a curated, redacted, step-indexed replay of a real agent run in a site-owned JSON schema. Each step carries a short author annotation, 1-3 citations into the official docs, and optional learner checkpoints. There are two kinds: 'pydantic_ai_run' (tracks 1-2) and 'claude_code_session' (track 3, merged with the PR's GitHub timeline). Ask the owner to confirm this meaning before building.
- SCHEMA (Pydantic model → JSON): TraceTranscript{id/slug, track, lesson_ids[], title, objectives[], difficulty, fade_level(0=fully annotated..2=learner annotates); source{kind, generator('FunctionModel'|'openai:…'|'claude-code'), lib_version (pydantic-ai / Claude Code version), model, captured_at, script_path, git_sha, pr_url?, logfire_trace_id?}; redaction{ruleset_version, tools[], human_reviewed:bool, reviewed_at}; steps[{idx, kind: user_prompt|instructions|model_request|thinking|model_text|tool_call|tool_result|retry|final_output|git_commit|pr_opened|ci_check|review_comment|merge, actor, title, summary, payload_excerpt (redacted, truncated), metrics{input_tokens, output_tokens, cost_usd, duration_ms}, annotation{why, concept_tags[], citations[{url, anchor, chunk_id, quote≤25 words}]}, checkpoint?{type: predict_next|mcq|spot_the_bug|self_explain, prompt, options?, answer?, rubric_id?, hints[3]}}], questions[{prompt, rubric{criteria[], expert_answer (context only)}, linked_steps[]}], takeaways[]}. Keep a separate raw_ref (ModelMessagesTypeAdapter JSON or normalized events) that is never served to the tutor.
- PIPELINE A (Pydantic AI): put scripts in traces/scripts/*.py. Each script builds a small agent and drives it with 'async with agent.iter(...)' to record nodes and stream events, then saves result.all_messages_json(), validates it with ModelMessagesTypeAdapter, and normalizes it into steps. Default to FunctionModel with scripted, realistic tool calls (deterministic, no API cost, runs in CI with ALLOW_MODEL_REQUESTS=False). Add a '--live' flag to capture a real-model run once and freeze it. Optionally run with logfire.configure() and instrument_pydantic_ai() to show the same run in Logfire, and pass run_id=<slug> so steps can deep-link to spans during the 30-day window. Add a GitHub Actions snapshot test that re-runs the FunctionModel scripts when pydantic-ai is bumped and diffs the step structure, flagging drift. This also doubles as a track-3 CI lesson.
- PIPELINE B (Claude Code + GitHub): add a SessionEnd hook that copies transcript_path to a private inbox outside the repo (e.g. ~/trace-inbox), and raise cleanupPeriodDays so sources survive curation. Pick sessions with 'claude --from-pr N'. Normalize with a tolerant, whitelist-based parser: keep user text, assistant text, tool_use name plus summarized input, and truncated tool_result; drop attachment, file-history and queue records; include thinking only as short flagged excerpts. Merge in 'gh api' PR timeline, reviews and check-runs to produce git_commit, pr_opened, ci_check, review_comment and merge steps. Redact (sanitizer + secret scan + path rewrite), set human_reviewed=true by hand, then commit the redacted JSON through a PR. The first worked example should be the PR that adds the trace player itself.
- STORAGE: the git repo is the source of truth (content/traces/<track>/<slug>.trace.json, reviewed via PRs, a natural track-3 exercise). Load into Neon: trace_transcripts(id, track, jsonb, version, content_hash), trace_steps(trace_id, idx, kind, annotation, citations jsonb), and RAG chunks in the shared pgvector table with source_type='trace'. Raw JSONL and raw messages never go into the repo or Neon. Do not use Logfire as storage (30-day retention, ≤500 query-API requests/day on Personal).
- RAG POLICY: embed one chunk per step (title + summary + annotation + citation titles), never raw payloads. Official docs are the only citable authority: the tutor may say 'like step 4 of the weather-agent trace', but every factual claim must cite a doc URL. Trace chunks act as worked-example retrieval, boosted when the learner is on that lesson. Store canonical pydantic.dev/docs/ai/... URLs. During the scheduled docs re-sync, hash each chunk and open a GitHub issue or PR listing traces whose cited chunks changed or vanished. Treat all trace payload text as untrusted data in prompts, since it may contain prompt-injection-like tool output.
- LESSON UX (fun, not docs): a step-through player with a progress bar, a token/cost meter and collapsible raw JSON. Before each tool call it pauses for 'predict what the agent does next' (MCQ, auto-graded). At 1-2 steps per trace it asks for a self-explanation, graded ESSE-style: correct/incomplete flags, then hint 1, hint 2, then the annotation reveal. Fade annotations across a trace series (full → partial → learner writes them), finishing with a 'spot the first failure' trace graded against the author's annotation.
- LOGFIRE AS SUBJECT, NOT INFRASTRUCTURE: track 1 lesson 'instrument your agent and read its trace' (instrument_pydantic_ai, Live view, token/cost badges). Track 3 lesson 'Claude Code + Logfire MCP': add the hosted MCP server and ask Claude Code to explain a retry, practising MCP in a GitHub flow. Keep Logfire optional so the site works without an account; local OTel via send_to_logfire=False is the fallback.
- RELEASE 1 SCOPE: 3 Pydantic AI FunctionModel traces (hello agent; tool call + ModelRetry; structured output with validation failure), 1 frozen real-model trace, 1 FastAPI-endpoint-calling-agent trace, and 2 Claude Code worked examples (feature branch → PR → CI fail → fix → review → merge; a branch-protection or required-check block). Use claude-code-log or claude-code-transcripts only for private browsing while curating.

### Risks
- The Claude Code JSONL format is officially internal and changes between versions, and 11+ record types were observed locally. A direct parser will break silently. Mitigate with a whitelist-tolerant normalizer, recording the Claude Code version per trace, and committing only normalized output.
- Sources disappear: Claude Code deletes transcripts after 30 days by default (cleanupPeriodDays), and Logfire Personal keeps spans 30 days. Public trace links die at retention even when set to 'Never'. Curate within days or raise retention.
- Secret and PII leakage: tool_result blocks contain file contents and command output (env vars, tokens), cwd contains the macOS username, and thinking text can mention anything. The available sanitizer skips prose PII, and Claude Code's built-in redaction has had recent gaps. A human-review gate is mandatory, even for a private site.
- Staleness: Pydantic AI moves fast (run_id/conversation_id, the docs domain move to pydantic.dev/docs/ai, instrumentation versions 5→6). Frozen real-model traces and annotations can contradict current docs. Mitigate with CI re-generation of FunctionModel traces and citation-hash checks in the docs re-sync.
- Trace content treated as authority or instructions: if the tutor cites trace text instead of docs, or ingests tool output with injection-like text, answer quality and safety suffer. Restrict citations to doc chunks and quote trace payloads only as data.
- TestModel traces look fake (placeholder 'a' arguments) and would undermine the 'real agent' feel. Use FunctionModel with realistic scripted arguments or frozen real runs.
- Quotas: Logfire Personal allows ≤500 query-API requests/day and the MCP server has a low daily budget, so live querying from the site, or heavy MCP use during lessons, can hit limits.
- Scope creep for a solo learner on a low-RAM Mac: building a generic transcript viewer or adopting Electron viewers (claude-devtools) is unnecessary. A small Python normalizer plus a site player is enough.
- Research limitation: Tavily returned HTTP 432 (plan usage limit) after 3 successful searches, so later cross-checks used Firecrawl, Octen, gh api and curl only. Star counts and versions are as of 2026-10-14.
