# Learning science → design rules

_Research archive. Checked against primary sources on 2026-10-14. Facts about fast-moving tools (Claude Code, Pydantic AI, FastAPI, GitHub, OpenRouter) go stale quickly: re-check before relying on a number._

- **Needed by:** Phase 1
- **Licence / attribution notes:** Papers cited by link (PubMed/PMC/arXiv).

## Evidence-based learning design for a private Pydantic AI / FastAPI / GitHub-in-the-Claude-Code-era learning site: retrieval practice, spacing (FSRS), question formats, guarded AI tutor, LLM-as-judge for open answers, and gamification

**Summary.** The research supports building every lesson around retrieval rather than reading. Classroom quizzing gives about g = 0.50 over 222 studies. Feedback works best when it carries information (d = 0.48), so every quiz option should explain the misconception behind it, not just mark right or wrong. Interleaving helps when concepts are easy to confuse (g = 0.42 overall) but can hurt for word-like material, so mix confusable pairs such as merge vs rebase, not everything. For spaced review there is a maintained, MIT-licensed Python package, fsrs 6.3.2 (released 2026-08-09, Python >= 3.10). Its core has no heavy dependencies; only the optional optimizer pulls in torch. The current srs-benchmark (about 10k Anki users, about 727M reviews) no longer lists SM-2, so a current FSRS-vs-SM-2 number could not be confirmed; FSRS-6 and FSRS-7 lead its tables. The strongest AI-tutor evidence is Bastani et al. (PNAS 2025). An unguarded GPT-4 raised practice scores 48% but lowered the unaided exam 17%. A tutor that was given the solution and never returned the answer raised practice 127% and removed the exam harm, but gave no exam gain. So the tutor should protect learning, while retrieval and practice do the teaching. Programming hint studies point to a short ladder of hint levels. A worked example on a different problem resolves most "what's the next step" and syntax questions, and when a student stays stuck, fixing the specific error beats repeating Socratic questions. LLM grading of short answers can come close to human agreement (kappa 0.70 vs 0.75 between humans) with binary per-criterion rubrics, rubric explanations aimed at the grader's own mistakes, and a majority vote over several runs. It can also fail badly (kappa about 0 on evaluative items), is open to prompt injection and persuasive wording, and its biases differ by model, so it must be checked against 30-50+ answers the owner grades by hand. Gamification has small positive average effects (g = 0.49 on learning), but points, badges and leaderboards are the most common source of harm. Streaks motivate while unbroken and demotivate once broken unless they can be repaired, so for a solo adult learner use mastery maps, forgiving weekly streaks and effort-based rewards, and no leaderboards.

### Findings

- **Quizzing reliably boosts classroom learning: g = 0.499 across 222 independent studies (48,478 students). Moderators include matching test formats, corrective feedback and the number of test repetitions.** [high] _(via Firecrawl (research_search_papers + scrape of PubMed abstract))_
  Yang, Luo, Vadillo, Yu, Shanks 2021, Psychological Bulletin 147(4). Supports making the quiz, not the reading, the core of each lesson, and repeating retrieval over time. Related: both multiple-choice and short-answer quizzes improved later exams in middle/high school classes (pmid 24274234).
  Source: <https://pubmed.ncbi.nlm.nih.gov/33683913/>
- **Feedback has an average effect of d = 0.48 (435 studies, N > 61,000). High-information feedback works best, reinforcement/punishment least. Effects are larger on cognitive than on motivational outcomes.** [high] _(via Firecrawl (research_search_papers + scrape))_
  Wisniewski, Zierer, Hattie 2020, Frontiers in Psychology. Implication: every multiple-choice option needs an explanation of why it is wrong or right (the misconception it represents), not just a 'Correct!' or a points award.
  Source: <https://pmc.ncbi.nlm.nih.gov/articles/PMC6987456/>
- **Interleaving has a moderate overall effect (g = 0.42) that depends on how similar the items are: g = 0.67 for paintings, 0.34 for math, null for expository text, and blocking wins for word lists (g = -0.39).** [high] _(via Firecrawl (research_search_papers + scrape))_
  Brunmair & Richter 2019, Psychological Bulletin (59 studies, 238 effect sizes). Interleaving works through discriminative contrast, so use it in review across easily confused concepts (merge vs rebase vs squash; Depends vs middleware; tools vs output validators). Keep the first exposure to a concept blocked.
  Source: <https://pubmed.ncbi.nlm.nih.gov/31556629/>
- **A maintained Python FSRS package exists: 'fsrs' 6.3.2 on PyPI, released 2026-08-09. MIT license, requires Python >= 3.10, and its only runtime dependency is typing-extensions. The optional [optimizer] extra pulls in torch, numpy and pandas.** [high] _(via Firecrawl developer_search (py-fsrs README) + read-only PyPI JSON API via curl + gh api)_
  API: from fsrs import Scheduler, Card, Rating, ReviewLog; scheduler.review_card(card, Rating.Good). Ratings are Again=1, Hard=2, Good=3, Easy=4. Default desired_retention is 0.9; learning_steps default to 1 min and 10 min; maximum_interval and enable_fuzzing are configurable. GitHub repo open-spaced-repetition/py-fsrs: not archived, last push 2026-08-09, 509 stars, 0 open issues (gh api). Recent releases: 6.1.0 (2025-06), 6.2.0 (2025-10), 6.3.0 (2025-10), 6.3.1 (2026-03), 6.3.2 (2026-08). Keep the optimizer extra out of the Vercel bundle.
  Source: <https://pypi.org/project/fsrs/>
- **The current open srs-benchmark (9,999 Anki collections, ~727M reviews, time-series split) ranks FSRS-7 and FSRS-6 near the top. FSRS-6 scores Log Loss 0.3460 and RMSE(bins) 0.0653 vs Ebisu v2 0.4989 / 0.1627 and HLR 0.4694 / 0.1275. SM-2 is no longer listed in the README tables.** [medium] _(via Firecrawl (scrape) + read-only curl of raw README; Anki FAQ via Firecrawl developer_search)_
  FSRS-7 (recency weighting) reaches Log Loss 0.3370. A trivial MOVING-AVG baseline is competitive on log loss, which suggests the gaps are modest in absolute terms. Anki's FSRS FAQ says FSRS gives longer first intervals than SM-2 but is more conservative for mature cards, and suggests re-optimizing about monthly or each time the review count doubles. A current numeric FSRS-vs-SM-2 comparison could not be confirmed from the live README.
  Source: <https://github.com/open-spaced-repetition/srs-benchmark>
- **Spaced-repetition schedulers were built for flashcard-style memory. Applying them to multi-skill items is an approximation; models that track per-skill forgetting (e.g., DAS3H) were proposed precisely because standard schedulers stop at pure memorization.** [medium] _(via Firecrawl (research_search_papers))_
  Choffin et al. (arXiv 1905.06873) argue adaptive schedulers are limited to pure memorization and add skill tagging plus forgetting. For this site: schedule FSRS cards per concept or question, not per whole lesson, and treat hands-on tasks as separate mastery evidence.
  Source: <https://arxiv.org/abs/1905.06873>
- **No single mastery threshold fits all learner models. Across 6 knowledge-tracing models, 4 datasets and 12 thresholds (0.50-0.99), the best-balanced threshold varied widely, and stricter thresholds did not reliably improve outcomes while adding practice burden.** [medium] _(via Firecrawl (research_search_papers))_
  arXiv 2610.00095 (2026 preprint). BKT was insensitive to threshold changes; neural models became much more selective as thresholds rose. Separately, over-practice of already-mastered skills is a known cost; fast-forwarding cut it by up to one third in simulation (arXiv 2506.17577). Implication: use a simple, tunable rule (e.g., >= 80% plus correct recall on two separate days), log it, and adjust it.
  Source: <https://arxiv.org/abs/2610.00095>
- **Hypercorrection: errors made with high confidence are more likely to be corrected after feedback than low-confidence errors. The effect persists over a week, but high-confidence errors can come back.** [high] _(via Firecrawl (research_search_papers))_
  Butterfield & Metcalfe 2001 (pmid 11713883); a classroom replication (pmid 29781391); Butler, Fazio & Marsh 2011 (pmid 21989771) on errors returning. Supports a lightweight confidence tag on each discrete item, and re-testing confident errors later instead of treating one correction as done. Certainty-based marking has been used in medical and physiology courses (pmid 41106847, PMC8834968).
  Source: <https://pubmed.ncbi.nlm.nih.gov/21989771/>
- **Asking questions before the reading (prequestions or pretests) usually improves learning from text, with small-to-medium effects vs reading or learning objectives. It does not always work.** [medium] _(via Firecrawl (research_search_papers))_
  pmid 41248075 (2025, prequestions vs learning objectives); pmid 33090823 (the generative part of pretesting improves conceptual learning for novices); pmid 29723010 (conditions where pretesting fails); pmid 34486928 (giving some context boosts the benefit). Related productive-failure work (pmid 24628487): attempting problems before instruction improved conceptual understanding and transfer.
  Source: <https://pubmed.ncbi.nlm.nih.gov/41248075/>
- **Parsons problems (rearranging code blocks) work as scaffolding: they improved practice performance and efficiency for low-self-efficacy learners (N = 89 RCT). LLM-personalized Parsons puzzles kept learners practicing longer than being shown full LLM solutions.** [high] _(via Firecrawl (research_search_papers))_
  arXiv 2311.18115 (N = 89, between-subjects); arXiv 2501.09210 (classroom RCT: Parsons scaffold vs complete solution on help request). Caveat: learners can order blocks without understanding them (arXiv 2401.03144). Faded Parsons problems were seen as a desirable challenge (arXiv 2512.22407). Guided Parsons with step hints raised post-test accuracy and efficiency (arXiv 2505.04712, N = 76). Suits git-flow ordering and FastAPI/Pydantic AI code assembly.
  Source: <https://arxiv.org/abs/2311.18115>
- **Multiple-choice distractors should encode known misconceptions. Misconception-driven generation measurably lowers guessing: a concept-map approach cut guess success to 28.05% vs 37.10% for baselines, and preference-trained distractors raised the item discrimination index on Python, database and ML questions.** [medium] _(via Firecrawl (research_search_papers))_
  arXiv 2505.02850 (concept-map MCQ generation); arXiv 2501.13125 (distractors that predict student choices, CS subjects); arXiv 2308.03234 (auto distractor plus per-distractor feedback). For this site: author 3 distractors per item, each tagged with a named misconception, and write per-option feedback.
  Source: <https://arxiv.org/abs/2501.13125>
- **Bastani et al. (PNAS 2025, ~1,000 high-school students): unguarded GPT-4 ('GPT Base') raised practice grades 48% but cut unaided exam grades 17% vs control. A guarded 'GPT Tutor' raised practice 127% and removed the exam harm, but produced no positive exam effect.** [high] _(via Firecrawl (research_search_papers; scrape of PubMed 40560616) + Octen (broad_search; extract of PMC full text))_
  GPT Tutor's prompt included the teacher's correct answer, and it 'does not return an answer by design'. GPT Base often gave incorrect answers through hallucination. Lesson: hints-before-answers plus grounding prevents harm, while durable learning still has to come from unaided retrieval and practice. Correction notice (pnas.2518204122) only fixed an author affiliation.
  Source: <https://pmc.ncbi.nlm.nih.gov/articles/PMC12232635/>
- **Harvard's CS50 Duck pairs 'pedagogical guardrails' (guide students rather than hand out solutions) with retrieval over course material. Lecture captions were embedded (text-embedding-ada-002, ChromaDB), and the top-N segments go to GPT-4 with the student query. It is available on the web and inside VS Code.** [high] _(via Tavily (search; the only Tavily call that succeeded) + Octen (extract of the PDF) + Octen broad_search (CS50 pages))_
  Liu et al., SIGCSE 2024, 'Teaching CS50 with AI'. A 2025 follow-up ('Improving AI in CS50', SIGCSE TS 2025) describes a centralized backend on GPT-4o with an instructional system prompt that also corrects outdated responses, improved through human feedback. This is close to the planned docs-RAG tutor, just over official docs instead of lecture captions.
  Source: <https://cs.harvard.edu/malan/publications/V1fp0567-liu.pdf>
- **Khan Academy's 2025-26 Khanmigo A/B tests: a summary of the student's recent problem history raised next-item correctness 3.4%, and surfacing unmastered prerequisites raised it 2.7%. Restricting the math agent to the student's own work cut answer give-aways by 50%. Adding examples of other problem types had no effect.** [medium] _(via Octen (search) + Firecrawl (scrape))_
  Tracked core metrics: response latency, next-item correctness, cognitive engagement. Guardrail metrics: 'giving the answer away before a student submitted a response', math error rate, interactions per thread. A concise-response instruction cut mean latency by about 3 s. These are vendor-reported, not peer-reviewed. Sal Khan's 2026 note says Khanmigo now prompts students to explain how they reached an answer.
  Source: <https://blog.khanacademy.org/how-khan-academy-is-building-a-better-ai-tutor-our-most-recent-learnings>
- **In a 4-level programming hint study (orientation -> instrumental -> worked example -> bottom-out code), worked-example hints resolved most next-step and syntax requests. High-level hints alone sometimes misled or frustrated novices; logic-debugging requests were often solved by high-level hints.** [medium] _(via Firecrawl (research_search_papers + research_read_paper))_
  arXiv 2404.02213 (LLM Hint Factory, think-aloud, n = 12). In 59% of instances, correct code changes came after the worked-example hint. Of learners who improved pre-to-post, 75% needed only up to the worked example and 25% needed bottom-out. All 3 misleading hints were high-level. Supports 4-6 hint levels whose worked example uses a different problem.
  Source: <https://arxiv.org/abs/2404.02213>
- **A deployed LLM tutor enforced answer-withholding as a per-turn contract. An 8-rung help ladder (H0 encourage ... H4 approach in words, no code; H5 worked example on a different problem; H6 pseudocode with blanks; H7 full solution) had its ceiling set by non-LLM code from trusted learner state. A deterministic detector stripped solution code, and an LLM judge checked risky replies.** [medium] _(via Firecrawl (research_search_papers + research_read_paper))_
  Pisan 2026, arXiv 2608.12292. Rules: a blunt demand for the solution never raises the ceiling; a student showing buggy code gets a floor at H4 (verbal help) so honest debugging is not over-blocked. The pre-classifier treats the message as data and outputs only an enum, so a successful injection causes at worst a wrong route. Ceiling compliance went from about 77% to 100% over iterations. Evaluation used simulated personas, not learners.
  Source: <https://arxiv.org/abs/2608.12292>
- **When a learner stays stuck, each extra impasse turn lowered the odds of recovering on the next turn by 12.7% (AOR 0.873). The benefit of Socratic questioning fell as the impasse deepened. After a failed scripted question, addressing the error directly led to recovery 39.8% of the time vs 28.1% for repeating the question.** [medium] _(via Firecrawl (research_search_papers))_
  arXiv 2609.38346 (20,462 turns, 1,260 sessions, guided chemistry tutor). Escalation rule: after about 2 unproductive Socratic turns, name and address the specific error instead of asking another question.
  Source: <https://arxiv.org/abs/2609.38346>
- **Strict guardrails cause friction and bypass. With an optional 'See Solution' that disabled guardrails, 50% of 885 students used it at least once and 14% on every problem, more often low performers and near deadlines. In an RCT (N = 132), the Socratic, full-context AI TA was rated least supportive and showed the highest external-LLM use (not significant).** [medium] _(via Firecrawl (research_search_papers))_
  arXiv 2504.11146; arXiv 2609.29995. A preregistered experiment (N = 704, arXiv 2609.20143) found that metacognitive feedback about the cost of offloading reduced answer offloading (OR 0.47) and improved the unaided test (OR 1.51), while an effort-based reward had no effect. Implication: keep the reveal available but make its learning cost visible, and do not count on points to deter it.
  Source: <https://arxiv.org/abs/2609.20143>
- **LLM short-answer grading can approach human agreement. GPT-4 few-shot reached Cohen's kappa 0.70 vs 0.75 between teachers (1,710 binary-graded answers); few-shot added little over zero-shot (0.68 -> 0.70). Disagreements clustered on partially correct answers.** [high] _(via Firecrawl (research_search_papers + research_read_paper))_
  arXiv 2405.02985 (Carousel, K-12 science/history, temperature 0). A 2026 study on MCAS data (arXiv 2606.12422) also found substantial QWK in math and science with Claude Sonnet 4, GPT-5 and others, but more variation in ELA. Teachers trusted narrative feedback more than numeric scores.
  Source: <https://arxiv.org/abs/2405.02985>
- **LLM grading can also fail badly. ChatGPT-4o grading postgraduate short answers (557 responses) showed ICC 0.086 and kappa -0.08, was systematically harsher (-1.34 on a 10-point scale), and did worst on evaluative and analytic items. Checklist-style rubric items disagreed less.** [high] _(via Firecrawl (research_search_papers))_
  arXiv 2505.04645. Similarly, GPT-4o graded more stringently in ambiguous cases and missed synonyms not in the rubric (arXiv 2411.03659). By contrast, a judge study found a general tendency toward leniency (arXiv 2406.12624). The direction of bias depends on model and task, so calibrate for your own setup.
  Source: <https://arxiv.org/abs/2505.04645>
- **Rubric design levers that worked: (1) binary yes/no rubric items; (2) explanation text on each rubric item aimed at the grader's observed errors; (3) 5 runs with a majority vote. Together they gave 70-80% agreement, equal to or above agreement between human graders. Disagreement across runs (entropy) flagged 40% of wrong grades by reviewing only 10-15% of answers.** [medium] _(via Firecrawl (research_search_papers + research_read_paper))_
  arXiv 2412.06910 (GPT-4o, physics explanations, 3-item binary rubric). Too little or too much rubric explanation hurt, and reference answers or few-shot examples can narrow what the grader accepts. A related study (arXiv 2601.08843) found alignment strong for binary tasks but degrading with finer rubric granularity, with confidence-based deferral raising accuracy on the retained cases. CHiL(L)Grader (arXiv 2603.11957) auto-scored 35-65% of answers at QWK >= 0.80 and routed the rest to humans.
  Source: <https://arxiv.org/abs/2412.06910>
- **Practitioner calibration recipe (Husain & Shankar): prefer binary pass/fail over Likert. Split hand-labeled examples into train (10-20%, usable as few-shot examples), dev and test sets. Report true-positive and true-negative rates, with 30-50 Pass and 30-50 Fail examples in dev and test. Expect criteria drift.** [medium] _(via Firecrawl (scrape) + Octen (broad_search for practitioner syntheses and arXiv 2606.00093) + Firecrawl developer_search (pydantic_evals docs))_
  The evals FAQ (dated 2026-09-18) says to plan 100-200 labels per failure mode at scale. 'Who Validates the Validators' (arXiv 2404.12272) documents criteria drift: grading outputs changes your criteria. For binary verdicts, Pearson, Spearman, phi and MCC are the same number; Cohen's kappa adds information about the judge's pass-rate drifting from the human's (arXiv 2606.00093). The pydantic_evals LLMJudge evaluator supports a rubric, include_input, and score plus assertion outputs with reasons, which fits a CI eval for the grader.
  Source: <https://hamel.dev/blog/posts/evals-faq/>
- **LLM judges have documented biases: position, verbosity, self-enhancement and style. In one 2026 comparison, style bias (preferring markdown) dominated at 0.10-0.76; verbosity bias varied by model family (some preferred longer answers by +0.24 to +0.44, Claude preferred concise at -0.12, GPT-4o was neutral).** [medium] _(via Firecrawl (research_search_papers))_
  Zheng et al. MT-Bench (arXiv 2306.05685) introduced position, verbosity and self-enhancement bias; arXiv 2604.23178 covers style and verbosity by model; arXiv 2504.09946 found 'superficial reflection' phrases sway reasoning-model judges. Mitigations: the rubric explicitly says length and formatting earn nothing, criteria are about specific claims, and a 'reason before verdict' structure is used.
  Source: <https://arxiv.org/abs/2604.23178>
- **Student answers can manipulate LLM graders. Rubric-based automatic graders were 'highly vulnerable' to prompt injection. Prompt-level defenses (trust-boundary delimiters, a check that enumerates manipulation patterns, a final rubric/score-range constraint) helped only partially. Persuasive wording inflated scores on wrong solutions by up to 8%.** [medium] _(via Firecrawl (research_search_papers + research_read_paper))_
  arXiv 2606.03090 (defenses 1-4 tested; attention analysis shows defense is partial); arXiv 2402.14016 (universal phrases inflate absolute scores more than comparative assessment); arXiv 2508.07805 (persuasion); arXiv 2602.00979 (GradingAttack). One study found Qwen-72B resilient to injection but sensitive to synonym swaps (arXiv 2601.08843). In a single-owner private site the threat is low, but the same pipeline would later face real users.
  Source: <https://arxiv.org/abs/2606.03090>
- **Gamification has small positive average effects (Sailer & Homner 2020: cognitive g = 0.49, motivational g = 0.36, behavioral g = 0.25). Only the cognitive effect held up in more rigorous studies. Badges, leaderboards, competition and points are the elements most often reported as causing harm.** [high] _(via Octen (search) + Firecrawl (research_search_papers))_
  Meta-analysis in Educational Psychology Review 32:77-112. Game fiction and combining competition with collaboration moderated behavioral outcomes. A systematic map of 87 papers (arXiv 2305.08346) lists lack of effect, worse performance, motivational problems and gaming the system. A systematic review (PMC10448467) notes novelty effects and motivation declining over time.
  Source: <https://link.springer.com/article/10.1007/s10648-019-09498-w>
- **Streaks motivate while intact, but highlighting a broken streak lowers later engagement, especially when users blame themselves. Allowing repair reduces the drop. Duolingo's A/B tests found that separating the streak from the daily goal raised day-14 retention 3.3%, and streak freezes help.** [high] _(via Octen (search: JCR record, Colorado summary, Duolingo blog))_
  Silverman & Barasch 2023, Journal of Consumer Research 49(6):1095-1117: 7 studies. The authors advise not notifying about broken streaks, counting weekly rather than daily, and offering repair. Duolingo blog figures (vendor-reported): 7-day streakers 2.4x more likely to return the next day; separating goal and streak +3.3% D14 retention.
  Source: <https://psycnet.apa.org/record/2023-60266-009>

### Recommendations
- RULE 1 (Lesson open): Start each lesson with 1-2 ungraded prequestions (predict-the-output, 'what happens if...', or 'which step comes first'). Show the answers only after the reading. Keep each reading chunk short (about 3-5 minutes) and follow it immediately with retrieval; never show a 'reread' view while an item is open.
- RULE 2 (Quiz formats per track): Pydantic AI / FastAPI: predict-the-output, fill in the blank in a code snippet, spot-the-bug, faded Parsons (assemble an Agent with tools, or a FastAPI route with Depends). GitHub track: Parsons ordering of the branch -> commit -> push -> PR -> review -> merge flow; 'Is this PR ready to merge?' scenario cards (failing check, unresolved review thread, stale base, missing required review under branch protection); spot-the-bug in a GitHub Actions YAML file. Use 4-6 items per lesson and mix formats.
- RULE 3 (Multiple choice that teaches): Give every item 3 distractors, each tagged with a named misconception (stored as data), plus per-option feedback explaining why it is tempting and why it is wrong. Give feedback right after each item. Allow a second try only after the learner reads the explanation for the option they chose; the second try counts as 'Hard', not 'Good'.
- RULE 4 (Confidence tagging): Add a one-tap confidence choice (Sure / Think so / Guessing) to every discrete item. A confident wrong answer gets a prominent 'surprise' callout, is re-asked as a sibling (isomorphic) item later in the same session, and is forced back into review at +1 day. Tagged misconceptions are what the system tracks, not only the item.
- RULE 5 (Spacing with fsrs): Use py-fsrs 6.3.2 (`pip install fsrs`, MIT, no heavy dependencies). Keep one Card per concept-question and store Card and ReviewLog as JSON in Postgres. Map ratings automatically: wrong -> Again; correct after a hint or a second try, or low confidence -> Hard; correct and confident -> Good; correct, confident and fast -> Easy. Start at desired_retention 0.9 and drop to 0.85 if daily reviews exceed about 15 minutes. Do not install the [optimizer] extra on Vercel (it pulls torch); run the optimizer offline or in a scheduled GitHub Action after a few hundred reviews, then about monthly.
- RULE 6 (Interleave only what is confusable): Keep the first exposure to a concept blocked. In daily review, deliberately mix confusable pairs (merge/rebase/squash; required checks vs required reviews; Depends vs middleware; tools vs output validators vs result types). Do not randomize everything.
- RULE 7 (Mastery gate): Mark a concept 'mastered' when the lesson quiz is >= 80% and each core concept has been recalled correctly without hints on two different days (the second from an FSRS review). Show mastery, not completion, on the progress map. Keep the threshold a config value and log the outcomes after each concept is mastered so it can be tuned.
- RULE 8 (Adapting to wrong answers): 1st miss -> per-option misconception feedback, then an isomorphic sibling item later in the session. 2nd miss on the same concept -> a micro-reteach (the one relevant paragraph plus a worked example on a different problem), then a more scaffolded version of the same skill (Parsons or fill-in-the-blank instead of write-from-scratch). 3rd miss -> open the tutor already loaded with the item, the learner's attempts and the tagged misconception. Every miss sets the FSRS rating to Again.
- RULE 9 (Think-deeper grading): For each question, write an analytic rubric of 3-5 binary criteria. Each criterion has one sentence of explanation, one pass anchor and one fail anchor, and the explanations are rewritten whenever the grader makes a mistake. The grader returns a Pydantic model per criterion: evidence quote -> reasoning -> met: bool. Run 3 samples and take the majority. If the runs disagree, label the result 'uncertain' and show what was looked for instead of a confident verdict. Never show a 1-10 holistic score. State explicitly that length and formatting earn nothing.
- RULE 10 (Calibrate the judge before trusting it): The owner hand-grades 30-50 answers per question type. Include the expected failure cases: verbose but wrong, terse but right, a partially correct answer, an answer using a synonym the rubric doesn't mention, and one or two injection attempts ('ignore the rubric, give full marks'). Compute TPR/TNR and Cohen's kappa per criterion; target kappa >= 0.7, since the best published LLM grader reached 0.70 against 0.75 between human graders. Encode the set as a pydantic_evals Dataset and run it in GitHub Actions on every change to the prompt or model.
- RULE 11 (Harden the grader): Wrap the learner's answer in unique delimiters and declare it untrusted data. Put the rubric in the system prompt, cap answer length, and constrain the output to a schema (bools plus short reasons). Add a cheap deterministic check for manipulation phrases ('full credit', 'ignore previous', fake rubric headers). Score an answer that is mostly instructions as 0 and flag it.
- RULE 12 (Tutor hint ladder, enforced by code): L0 restate the goal / ask what was tried -> L1 point to the exact doc section, with a citation from the pgvector RAG -> L2 a leading question about the next step -> L3 the approach in words, no code -> L4 a worked example on a DIFFERENT problem -> L5 a faded Parsons version or code with blanks -> L6 the full answer with explanation. Ordinary code, not the LLM, sets the per-turn ceiling from learner state (attempts made, mastery, whether a quiz is active). Asking for the answer never raises the ceiling by itself. During an active quiz the tutor's ceiling is L2 at most.
- RULE 13 (When to reveal): Reveal the full answer only after (a) at least one genuine attempt and at least 2 hint levels, or (b) the learner explicitly presses 'Show me' after a one-line message about the cost ('revealing now schedules a re-test tomorrow; revealed items are usually forgotten faster'). Never block the reveal outright; blocking drives use of outside ChatGPT or Claude. Log every reveal, rate it Again in FSRS, and schedule the re-test.
- RULE 14 (Escalate out of Socratic loops): After 2 consecutive tutor turns where the learner makes no progress, stop asking questions. Name the specific error and give the next rung. Pass the tutor a compact summary of recent attempts, misses, tagged misconceptions and unmastered prerequisites (Khanmigo's tests found history and prerequisite context improved next-item correctness 2.7-3.4%). Track 'answer revealed before learner attempt' as a guardrail metric, with a deterministic filter that strips full solution code below L5.
- RULE 15 (Fun without the harm): Use a visual mastery map per track and confidence-calibration stats ('your Sure answers are right 92% of the time'). Use a WEEKLY streak with automatic freezes and an easy repair, and no broken-streak notifications. Award XP only for effortful acts (attempting before a hint, fixing a confident error, finishing a hands-on task that passes its checker), never for time spent or reveals. No leaderboard while the site has one user. Keep humor and story in the copy and scenarios, and use game fiction for the GitHub track (e.g., you are the reviewer on a messy PR) rather than point inflation.
- Hands-on tasks: give each one an automated checker (pytest or a GitHub Actions workflow run on the learner's practice repo). A pass counts as mastery evidence independent of the quiz; a fail goes to the same hint ladder, which sees the failing output.
- Item freshness: because the docs re-sync on a schedule, store the source doc-chunk hash on each quiz item and rubric. When a chunk changes, flag the dependent items for review, so stale answers aren't graded as wrong.

### Risks
- The LLM grader's bias depends on the model: it can be harsh (ChatGPT-4o on postgraduate answers: -1.34/10, kappa about 0) or lenient. A 30-50 item calibration set from one person gives a noisy kappa, and agreement degrades on evaluative or open-ended 'think deeper' items, which are exactly the item type used here.
- Guardrails cut harm but in the best RCT they produced no exam gain (Bastani: GPT Tutor exam effect about 0). Over-investing in the tutor at the expense of retrieval items and hands-on checkers would be a misallocation.
- Over-strict Socratic behavior frustrates learners and pushes them to unguarded tools (50% used 'See Solution'; the Socratic full-context TA was rated least supportive). For a solo owner, bypass is one browser tab away.
- FSRS is optimized for flashcard memory. Applying it to conceptual or procedural items (GitHub flow judgment, Pydantic AI design) is an approximation, and its default parameters come from Anki users. The current srs-benchmark README no longer reports SM-2, so a current FSRS-vs-SM-2 claim rests on older or secondary statements.
- Parsons and other scaffolded formats can be solved by pattern matching without understanding; they must be faded toward writing from scratch.
- Gamification effects on motivation are less robust under rigorous designs and fade with novelty. Daily streaks create anxiety, and broken streaks demotivate.
- Prompt-injection and persuasion attacks on the grader are only partly mitigated by prompt-level defenses. This is low risk in a private single-user Release 1, but real once accounts open.
- Several key sources are 2026 arXiv preprints (the 8-rung supervisor tutor, impasse dynamics, the metacognitive-feedback RCT, mastery thresholds) and vendor blogs (Khanmigo, Duolingo) that are not peer-reviewed.
- Running 3 grading samples plus RAG tutoring on Vercel adds latency and cost; serverless function timeouts may need streaming or background jobs.
- Engine limits during this research: Tavily returned 1 successful search, then failed with errors 429 and 432 (plan usage limit exceeded); tavily_research and tavily_extract also failed. Practitioner synthesis therefore relied mostly on Octen and Firecrawl.

### Open questions
- What FSRS card granularity should be used: per quiz item, per concept (with several item variants rotating), or both? How should hands-on task results feed FSRS ratings?
- What desired_retention suits a solo learner with limited daily time: 0.85 or 0.90? This should be revisited after about 4 weeks of review logs.
- Which model should grade and which should tutor? Verbosity and style biases differ by model family, so the calibration set must be re-run whenever the model changes.
- Will the owner hand-label 30-50 answers per think-deeper rubric up front, or should Release 1 start with binary 'met / not met / uncertain' feedback only and calibrate gradually?
- How should GitHub-track hands-on tasks be verified safely: a dedicated practice repo with Actions-based checkers vs local CLI checks? And how should the tutor see check output without exposing tokens?
- Should confidence tagging be a simple 3-level tag or full certainty-based marking with asymmetric scoring? The latter adds stakes that may feel less fun.
- How should quiz items and rubrics be versioned against docs re-syncs (Pydantic AI and FastAPI APIs change), so answer keys don't silently go stale?
- Did py-fsrs 6.x switch from FSRS-6 to FSRS-7 internally? The package version numbering suggests FSRS-6, but this was not confirmed from the source code.
