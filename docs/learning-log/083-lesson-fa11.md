This adds lesson FA11, "Bigger apps with APIRouter" (25 minutes), to the FastAPI track. The idea in one sentence: an `APIRouter` is a small app that holds routes and shared settings, and `include_router` plugs it into the real app, so the prefix, tags and checks are written once and `main.py` stays a short list. The reading has seven short sections. What a router is and a file layout for a split app. The settings on a router (`prefix`, `tags`, `dependencies`, `responses`) and the slips around prefixes and route paths. Settings added at include time, for a shared router you may not edit, and the order in which dependencies and tags stack up. Imports and running the package (relative imports, importing the module and not `router`, the `entrypoint` in `pyproject.toml`). Route order across routers. Tags and docs metadata (`openapi_tags`, summary, docstring, `deprecated`, and a test that reads `/openapi.json`). And routers staying live after they are included. The examples use recipes and cooks, and the task uses a pet shop.

The lesson has 2 warm-up predictions, 6 quiz items (4 single-choice with a named misconception on every wrong option, 1 ordering item, 1 fill-in-the-blank) and 2 think-deeper questions with 4 binary criteria each. The hands-on task starts from a flat pet-shop package. The learner moves the pet routes and the owner routes into two routers, puts the prefix, tag, key check and a documented `404` on the pets router, includes a shared admin router they must not edit with its settings given at include time, and adds `openapi_tags` in a set order. The 13 hidden tests (10 test functions, one of them run for 4 routes) read `/openapi.json` (paths, the tags on each operation and their order, the tag list, the `404` response, the key header) and call the routes with a test client (missing key is a 422, a wrong key is a 401, the right key is a 200). They also check that the key check is a dependency of the pets router, and that `admin.py` is unchanged. The starter fails them and the solution passes.

One lesson learned: most of the surprises were quiet. A route path written as `"x"` under the prefix `/b` was accepted and became `/bx`. A prefix written twice gave `/pets/pets/` with no error. Importing `router` from two files and including it twice dropped the first file's routes, and the only sign was a `Duplicate Operation ID` warning. A tag with no metadata stays on its route but is left out of the top-level tag list. We also ran what the page does not say: dependencies given to `include_router` run after the app's and before the router's, and include-time tags come first in a route's tag list.
