This PR adds a second place to keep learner data: Postgres on Neon, next to the SQLite file we already use. `PostgresStore` in `app/store_pg.py` has exactly the same methods as `SqliteStore`, so the rest of the app does not notice which one it is talking to. If `DATABASE_URL` is set the app uses Postgres, otherwise it keeps using SQLite, so nothing changes for phase 1. `app/pg_schema.sql` holds the same tables in Postgres form, plus the `pages` and `chunks` tables for phase 2 search (a pgvector column for meaning-based search, and a full-text column for keyword search). One surprise: Postgres refused the keyword column until the heading list was joined by a function marked "immutable", because the built-in join is only marked "stable". Run `uv run python scripts/migrate.py` to create the tables; it uses the direct Neon URL, because the pooled one (PgBouncer) does not suit schema changes. The same behavioural tests now run against both stores, and CI starts a Postgres service so they really run there; on a laptop without Postgres they skip. Read `app/store_pg.py` first, then `docs/runbooks/neon.md` for the one-time setup.
