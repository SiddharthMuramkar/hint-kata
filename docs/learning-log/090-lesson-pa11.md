This adds the Pydantic AI lesson "Production basics: Logfire, retries, usage limits" (`pa11-production-basics`, about 40 minutes, pinned to Pydantic AI 2.56.0 and Logfire 5.2.0). It teaches what to put around an agent before it runs when nobody is watching. First, the seven kinds of retry and which of them the model can see (only tool and output retries show up as a `RetryPromptPart`). Then the retry budgets: one `retries` argument, the counter that is kept per tool and cleared on success, and why `ToolFailed` does not use the budget. Then how retries stack (`N × F × M × K` requests in the worst case) and why `UsageLimits` only sees the turns. Then `UsageLimits` itself: `request_limit` (default 50), `tool_calls_limit`, the token limits and the best-effort `cost_limit`. Then how to reproduce a runaway loop in a test with a `FunctionModel`. The second half covers Logfire and OpenTelemetry: the two calls that switch tracing on, the shape of one run in a trace (an `invoke_agent` span with `chat` and `execute_tool` children), `include_content=False` to keep customer text out, and what the version policy lets change in a minor release (span attributes can).

The lesson comes with a warm-up of two questions, a six-item quiz (four single-choice, one ordering, one fill-in-the-blank), two think-deeper questions with four criteria each, and a hands-on task. In the task the learner edits `guard.py`: a research agent with a `search` tool that always works and a `fetch` tool that asks for a retry on a bad URL and raises `ToolFailed` for one host that is always down. The learner gives the tools a retry budget of 2, sets `UsageLimits(request_limit=5, tool_calls_limit=3)`, and writes `run_guarded`, which returns an `Outcome` instead of raising when a run is stopped. The hidden tests loop a `FunctionModel` forever on each tool and check the exact counts: 3 searches (stopped by `tool_calls_limit`), 5 failing fetches (stopped by `request_limit`, because a `ToolFailed` call is neither a successful call nor a retry), and 3 attempts for a tool that keeps asking for retries. They also check that a run with two bad URLs recovers, and that the code does not catch bare `Exception`. The starter fails these tests and the solution passes them (`tests/test_lesson_tasks.py`).

Things we saw that the lesson reports honestly. With no limits at all a looping run still stops, after 50 requests, so Pydantic AI has a built-in net, just a large one. A loop on a tool that raises `ToolFailed` is stopped only by `request_limit`, so the two limits are not interchangeable. `cost_limit` never fired on a fake model with no price, which is the docs' point that cost is best effort.
