This PR lets the tutor look things up. Until now it only knew the lesson text. Now, when the docs are in Neon (see `docs/runbooks/ingestion.md`), each question is turned into numbers (an embedding), the best six doc pieces from the lesson's own track are found with the hybrid search from the last PR (keywords plus meaning, merged by reciprocal rank fusion), and they are put in front of the tutor. A new `track` filter in `app/ingest/search.py` keeps a FastAPI lesson from seeing GitHub pages. The reply can cite a piece as `[src:1]`. The server checks every `[src:N]` against the pieces it really sent this turn and deletes the others, then adds each valid one to the `citations` event as `{n, title, url}`, where the url is the page URL plus the heading anchor. The page shows them in the `Sources:` line as links that open in a new tab. Lesson-section citations (`[§id]`), the hint ladder and the ceiling are untouched.

If anything is missing, the tutor works exactly as before. `app/retrieval.py` returns no hits when `DATABASE_URL` is not set, the tables are missing, the embedding key is missing or the database is slow (it gives up after 6 seconds), and it says why once in the log. `RAG_ENABLED=false` switches it off, and `RAG_K` sets how many pieces (default 6). Each turn logs how many pieces were found and their URLs, never their text. The site now prints its own INFO log lines, because uvicorn hides them by default.

Two choices to notice. The doc pieces are untrusted text, so they go in the learner's message inside a fenced block, capped at 1,200 characters each, with any `<<<` markers defused. They are not in the system instructions. Old `[src:N]` marks are also stripped from earlier replies before the chat history goes back to the model, because number 1 on one turn is a different piece on the next. When a filter is on, the search turns on pgvector's iterative scan so the filtered list does not come back short.

Read `app/retrieval.py` first (60 lines), then the route in `app/routes/tutor.py`, then `tests/test_tutor_rag.py`. The track-filter test is in `tests/test_ingest_pg.py` and runs in CI, not on a laptop without Postgres.

Lesson learned: keep what changes every turn out of what you cache. The tutor's instructions are marked for prompt caching, and the retrieved pieces are different on every question. Putting them in the instructions would have thrown the cache away each turn and put untrusted text in the most trusted place. Putting them in the user message fixes both problems with one decision.
