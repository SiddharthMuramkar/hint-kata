One lesson learned: `TestModel` makes up the arguments of every tool call (a string becomes "a", a number becomes 0.0), so a tool that checks its input raises `ModelRetry` and the run fails with `UnexpectedModelBehavior`. Test data has to fit what `TestModel` invents, or the test needs a `FunctionModel` script. A second surprise: when one model reply holds two tool calls, the tools start together, so a guard like "look up before refund" can fail by chance when the lookup is slow. Marking the tools `sequential=True` makes them run in order, and the support agent in the task does that.
